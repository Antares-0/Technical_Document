# Go并发


## 一、`Go`的`sync.noCopy`
1. 简介：是sync包<font color='yellow'>**内部**</font>的标记类型，用于禁止结构体被值拷贝（值拷贝：将一个变量的值完整复制到另一个变量中）。`sync.noCopy`只做静态检查，运行时完全不生效，不会panic，不占用内存。
2. 代码用法
   - `sync.noCopy`是未导出类型（未导出类型‌是指名称首字母为‌小写‌的类型标识符，仅在‌定义它的包内部‌可见和可访问，包外代码无法引用、声明或实例化该类型），如果自己想使用需要自己定义一套
     ```golang
     type noCopy struct{}

     func (*noCopy) Lock()  {}
     func (*noCopy) Unlock() {}

     type MyLock struct {
         _ noCopy // 匿名嵌入，go vet就会检测拷贝
         mu sync.Mutex
     }
     ```
   - 报错案例
     ```goland
     package main

     import (
         "fmt"
     )
     
     type myNoCopy struct{}
     
     func (*myNoCopy) Lock()   {}
     func (*myNoCopy) Unlock() {}
     
     type myOnce struct {
         _ myNoCopy
     }
     
     func main() {
         o1 := myOnce{}
         fmt.Println(o1)
         o2 := myOnce{}
         o1 = o2
     }
     
     // # awesomeProject
     // # [awesomeProject]
     // ./main.go:18:14: call of fmt.Println copies lock value: awesomeProject.myOnce contains awesomeProject.myNoCopy
     // ./main.go:20:7: assignment copies lock value to o1: awesomeProject.myOnce contains awesomeProject.myNoCopy
     ```
3. 场景用法
   - 禁止值拷贝的场景，需要使用
4. 原理
   - 如果一个类同时拥有`Lock()`和`Unlock()`方法，就会触发`go vet`检查，在一些值拷贝的场景就会被检查出来
5. 注意事项
   - `sync.noCopy`在运行时不会阻止拷贝，代码能运行，但是逻辑是错误的，只有执行`go vet`才报警
   - `sync.noCopy`也不会占用结构体内存
   - 使用`go vet`检查，以下几种情况会触发报警
     - 赋值拷贝：一个`sync.noCopy`类型的对象被另一个`sync.noCopy`赋值
       ```golang
       type T struct {
           sync.noCopy
       }

       var a T
       b := a // vet: assignment copies lock value to b: T contains sync.noCopy
       ```
     - 值传参拷贝：方法传入一个`sync.noCopy`对象
       ```golang
       func f(t T) {} // 值接收，会拷贝

       var a T
       f(a) // vet: function call copies lock value: T contains sync.noCopy
       ```
     - 结构体整体拷贝：数组赋值、切片赋值、struct 字面量拷贝、range 迭代取值，对象里面包含这样一个`sync.noCopy`的对象就会有问题
       ```golang
       // 数组赋值拷贝
       arr1 := [1]T{{}}
       arr2 := arr1 // vet copies lock value
       
       // range 取值拷贝
       s := []T{{}}
       for _, item := range s { // item 是拷贝，vet告警
       }
       
       // 结构体嵌入后整体赋值
       type Wrapper struct {
           obj T
       }
       w1 := Wrapper{obj: a}
       w2 := w1 // 连带内部 noCopy 结构体一起拷贝，触发告警
       ```

## 二、`Go`的`sync.Once`
1. 简介：`sync.Once`是golang的原生结构，专门用来确保某段代码在整个程序的生命周期只执行一次；其核心方法是`Do(func())`，用来执行特定的函数，无论调用多少次`Do()`，传入的`func()`也只会被执行一次
2. 代码用法
   ```golang
   package main

   import (
       "fmt"
       "sync"
   )

   var once sync.Once

   func main() {
       for i := 0; i < 5; i++ {
           once.Do(onceRun)
           fmt.Printf("第%d次执行结束\n", i)
       }
   }

   func onceRun() {
       fmt.Printf("onceRun")
   }
   
   // onceRun第0次执行结束
   // 第1次执行结束
   // 第2次执行结束
   // 第3次执行结束
   // 第4次执行结束
   ```
3. 场景用法
   - 单例模式
   - 一次性初始化
4. 原理
   - 源码角度分析
     ```golang
     type Once struct {
         _    noCopy

         done atomic.Bool
         m    Mutex
     }
     
     func (o *Once) Do(f func()) {
         if !o.done.Load() {
             o.doSlow(f)
         }
     }

     func (o *Once) doSlow(f func()) {
         o.m.Lock()
         defer o.m.Unlock()
         if !o.done.Load() {
             defer o.done.Store(true)
             f()
         }
     }
     ```
   - 关键点
     - `noCopy`用来表示这个结构体的对象不能做值拷贝（在传参数的时候不能生成全新副本）
     - `atomic.Bool`是原子布尔类型，底层的`Load()`和`Store()`带CPU内存屏障，禁止指令重排
     - `Mutex`保证了唯一性，当同时执行到`doSlow`函数的时候，能够保证最终只有一个同时在被调用
     - `atomic.Bool`和`Mutex`同时存在的理由：`atomic.Bool`用户快速判断是否已经执行过了函数；`Mutex`用于真正实现并发锁
5. 注意事项
   - `sync.Once`的`Do`方法里面不能调用自己，否则会死锁
     ```golang
     var once sync.Once
     func deadlock() {
         once.Do(deadlock) // 递归调用，死锁了！
     }
     ```
   - `sync.Once`的`Do`方法里面不能返回错误
