# 单例模式

## 一、单例模式介绍
1. 单例模式（Singleton Pattern）是创建型设计模式中最常用、最简单的模式之一。
2. 核心定义：确保一个类在整个应用程序的生命周期中，有且仅有一个实例对象，并提供一个全局统一的访问入口，供外部直接获取该实例。
3. 核心三大特性
   1. 私有构造方法：禁止外部通过 new 关键字手动创建实例，从根源保证实例唯一性
   2. 私有静态实例对象：类内部持有唯一的自身实例，私有化避免外部篡改
   3. 公共静态获取方法：对外提供统一的实例获取入口，控制实例的创建逻辑
4. 核心优势：减少对象频繁创建销毁的资源开销、统一全局状态、避免多实例冲突、简化全局资源管理

## 二、单例模式设计思想——什么时候用单例模式
单例模式的核心设计思想：全局只需要一个对象，多实例会造成资源浪费、数据冲突、逻辑异常，此时必须使用单例。
1. 适用场景（核心场景）
   - 全局配置类：系统配置、参数配置、常量配置，全局统一读取，无需多实例
   - 资源工具类：数据库连接池、线程池、缓存工具、日志工具，频繁创建实例会消耗大量系统资源
   - 状态统一类：全局状态管理、计数器、权限校验工具，多实例会导致状态不一致
   - 系统核心组件：Spring 容器、上下文环境、全局定时器，全局唯一即可满足所有业务需求
2. 不适用场景
   - 需要频繁实例化、销毁的临时业务对象
   - 存在多租户、多环境隔离需求，需要独立实例的场景
   - 需要动态扩展、继承重写的业务类

## 三、单例模式实战——Java版
Java 单例分为饿汉式、懒汉式（线程安全）、双重校验锁、静态内部类、枚举式，其中枚举式为最优实现，解决序列化、反射破坏单例问题。
1. 饿汉式（线程安全、简单、常用）：类加载时直接创建实例，天然线程安全，缺点是启动时占用少量内存。
   ```java
   public class SingletonHungry {
       // 1. 私有静态实例：类加载时初始化唯一实例
       private static final SingletonHungry INSTANCE = new SingletonHungry();
       // 2. 私有构造方法：禁止外部new
       private SingletonHungry() {}
       // 3. 公共静态入口：对外提供唯一实例
       public static SingletonHungry getInstance() {
           return INSTANCE;
       }
   }
   ```
2. 双重校验锁懒汉式（延迟加载、线程安全、高性能）：使用`volatile`禁止指令重排，兼顾延迟加载和多线程安全，业务开发最常用。
   ```java
   // 双重校验锁单例
   public class SingletonDCL {
       // volatile 防止指令重排，保证多线程可见性
       private static volatile SingletonDCL instance;
   
       private SingletonDCL() {}
   
       public static SingletonDCL getInstance() {
           // 第一次校验：避免每次进入同步锁，提升性能
           if (instance == null) {
               // 同步锁：保证同一时间只有一个线程创建实例
               synchronized (SingletonDCL.class) {
                   // 第二次校验：防止多线程穿透第一次校验重复创建
                   if (instance == null) {
                       instance = new SingletonDCL();
                   }
               }
           }
           return instance;
       }
   }
   ```
3. 枚举单例（最优、绝对安全）：`Java`枚举天然杜绝反射、序列化破坏单例，是推荐的最佳实现。
   ```java
   // 枚举单例
   public enum SingletonEnum {
       INSTANCE;
   
       // 自定义业务方法
       public void doSomething() {
           System.out.println("枚举单例执行业务逻辑");
       }
   }
   ```

## 四、单例模式实战——Go版
`Go`语言无类的概念，单例基于结构体、私有变量、同步锁、单次执行实现，核心保证全局结构体实例唯一。常用两种实现：sync.Once 极简版（推荐）、互斥锁双重校验版。
1. 核心思路 
   - 定义私有结构体，禁止外部直接实例化；
   - 定义全局私有实例变量，存储唯一对象；
   - 通过 `sync.Once` 或互斥锁控制实例仅创建一次；
   - 对外暴露公共`GetInstance`方法获取唯一实例。
2. 最优实现：`sync.Once`单例（线程安全、极简、高性能），`sync.Once`是 Go 官方提供的单次执行工具，天然保证并发安全，只会执行一次初始化逻辑，规避锁的性能损耗，是Go单例首选方案。
   ```go
   package main
   
   import (
   	   "fmt"
   	   "sync"
   )
   
   // 1. 定义私有单例结构体
   type singleton struct {
   	   // 可存储全局配置、状态、连接等字段
   	   Config string
   }
   
   // 2. 私有全局实例变量
   var instance *singleton
   
   // 3. sync.Once 保证初始化方法仅执行一次
   var once sync.Once
   
   // 4. 公共对外获取实例方法
   func GetSingletonInstance() *singleton {
   	   once.Do(func() {
   	   	   // 仅第一次调用时创建实例，后续直接跳过
   	   	   instance = &singleton{
   	   	   	   Config: "全局默认配置",
   	   	   }
   	   })
   	   return instance
   }
   
   // 测试单例唯一性
   func main() {
   	   s1 := GetSingletonInstance()
   	   s2 := GetSingletonInstance()
      
   	   // 对比内存地址，判断是否为同一个实例
   	   fmt.Printf("s1 地址：%p\n", s1)
   	   fmt.Printf("s2 地址：%p\n", s2)
   	   fmt.Println("是否为同一实例：", s1 == s2) // 输出 true
   }
   ```
3. 兼容实现：互斥锁双重校验单例
   ```go
   package main
   
   import (
   	   "fmt"
   	   "sync"
   )
   
   // 私有结构体
   type singletonDCL struct{}
   
   // 全局实例 + 互斥锁
   var (
   	   instanceDCL *singletonDCL
   	   mu          sync.Mutex
   )
   
   // 双重校验获取单例
   func GetDCLInstance() *singletonDCL {
   	   // 第一次校验：减少锁竞争，提升性能
   	   if instanceDCL == nil {
   	   	   mu.Lock()
   	   	   defer mu.Unlock()
   	   	   // 第二次校验：防止并发重复创建
   	   	   if instanceDCL == nil {
   	   	   	   instanceDCL = &singletonDCL{}
   	   	   }
   	   }
   	   return instanceDCL
   }
   
   func main() {
   	   s1 := GetDCLInstance()
   	   s2 := GetDCLInstance()
   	   fmt.Println("DCL单例是否唯一：", s1 == s2) // true
   }
   ```
