# 设计模式总纲

## 一、设计模式的意义
1. 设计模式是软件开发中用来解决特定问题的一套经验法则或者模板，它们是一套被广泛认可的解决方案，用以处理在软件设计过程中经常遇到的典型问题。从建筑学借鉴而来，设计模式在软件工程领域中占据着举足轻重的地位。
2. 设计模式的概念最早由建筑学领域中的“模式语言”引申到软件领域。在1994年，由`Erich Gamma`、`Richard Helm`、`Ralph Johnson`和`John Vlissides`四位作者共同撰写的《`Design Patterns: Elements of Reusable Object-Oriented Software`》一书正式出版，标志着软件设计模式理论体系的形成。这本书后来被广泛称为“四人帮（`Gang of Four`, `GoF`）的书”，其中描述了23种设计模式，被业界奉为经典。

## 二、设计模式原则概览
1. 单⼀职责原则：类的职责单⼀、⼀个类应该只负责⼀项职责
2. 接⼝隔离原则：只依赖⾃⼰有⽤的接⼝⽅法、⼀个类对另⼀个类的依赖应该建⽴在最⼩的接⼝之上
3. ⾥⽒替换原则：⼦类尽量不要重写⽗类的⽅法、子类型必须能够替换掉它们的父类型
4. 依赖倒转原则：不依赖实现类，依赖接⼝、抽象不应该依赖细节，细节应该依赖抽象
5. 开闭原则：对扩展开放，对修改关闭、增加功能的实现尽量通过扩展来实现，⽽不是修改
6. 迪⽶特法则：最少知道，细节不需要了解、⼀个对象应该对其他对象保持最少的了解
7. 合成复⽤原则：⽤组合或者聚合，⽽⾮继承、尽量使⽤合成或者聚合的⽅式，⽽不是继承

## 三、设计模式原则对应的实现方式
1. 单⼀职责原则
   - 业务角度：一个业务对应一个类，一件事只通过一个方法来实现
   - 代码角度：大类拆分为多个小类、代码分层、拒绝万能工具类（一个工具类里面放一堆无关的方法）
2. 接⼝隔离原则
   - 业务角度：按照能力划分接口
   - 代码角度：大接口拆分为多个小接口、面向多个小接口依赖、实现类只实现自己需要的接口
   ```java
   // 坏：胖接口
   public interface BigInterface{
       void edit();
       void delete();
       void query();
   }
   // 好：拆分成多个小接口
   interface QueryAbility{ void query(); }
   interface EditAbility{ void edit(); }
   ```
3. ⾥⽒替换原则
   - 业务角度：继承不能更改父类的行为
   - 代码角度：子类不能抛父类没有的异常、子类的入参不能比父类更严格、子类的返回值不能比父类更宽泛
4. 依赖倒转原则
   - 业务角度：对业务的抽象定义基本契约，并由具体实现类去实现
   - 代码角度：高层业务不能`new`具体实现类（要依赖抽象接口）
5. 开闭原则：对扩展开放，对修改关闭、增加功能的实现尽量通过扩展来实现，⽽不是修改
   - 业务角度：新增业务优先考虑新增代码而不是在老代码上进行修改
   - 代码角度：把不变的行为抽象成抽象代码、变化的部分做成不同实现、组合优于继承
6. 迪⽶特法则：最少知道，细节不需要了解、⼀个对象应该对其他对象保持最少的了解
   - 业务角度：一个业务只和周边直接相关的业务进行交互，跨业务的交互通过多重接口实现
   - 代码角度：内部属性私有化`private`、减少大量`import`、内部逻辑尽量不暴露给外部
   ```java
   // 违反迪米特：连续点获取内部对象
   int price = user.getOrder().getItem().getPrice();

   // 符合迪米特：提供封装方法，外部不用感知内部结构
   int price = user.getOrderTotalPrice();
   ```
7. 合成复⽤原则：⽤组合或者聚合，⽽⾮继承、尽量使⽤合成或者聚合的⽅式，⽽不是继承
   - 业务角度：多用组合而不是聚合
   - 代码角度：多用私有属性而不是继承、如果继承会破坏里氏替换原则就直接使用组合
   ```java
   // 组合：优先推荐
   public class Car{
      private Engine engine; //组合持有
   }
   
   // 继承：只有真正is‑a才用
   public class RedCar extends Car{}
   ```

## 四、设计模式分类
1. 创建型模式（类从哪里来）：创建对象时考虑的
   - 单例模式：保证一个类只有一个实例，提供全局访问点
   - 工厂方法模式：定义创建对象抽象方法，子类决定实例化哪一个类
   - 抽象工厂模式：创建一组相关的对象，不需要指定具体类
   - 建造者模式：分步构建复杂对象，相同构建过程得到不同产品
   - 原型模式：通过拷贝已有对象来生成新对象
2. 结构型模式（类之间怎么组装）：类、对象之间的组合，把现有的类组合成更大的结构、
   - 适配器模式：把一个接口转换成客户期望的另一个接口
   - 桥接模式：分离抽象与实现，二者可以独立变化
   - 装饰器模式：动态给对象增加额外职责，不修改原对象
   - 组合模式：树形结构，统一对待单个对象和对象集合（叶子 / 容器）
   - 外观模式：提供统一高层接口，隐藏子系统复杂细节（迪米特法则落地）
   - 享元模式：共享大量细粒度对象，减少内存占用
   - 代理模式：为对象提供一个代理，控制对原对象的访问
3. 行为型模式（类组装之后怎么实现业务）：对象之间通信、算法、职责分配、流程控制
   - 策略模式：封装一系列算法，可互相替换，算法变化独立于调用方（开闭）
   - 模板方法模式：父类定义算法骨架，子类实现部分步骤
   - 观察者模式：一对多，主题变化通知所有观察者
   - 迭代器模式：遍历集合，不暴露底层集合结构
   - 责任链模式：请求沿着处理链传递，链上对象依次处理请求
   - 命令模式：把请求封装成对象，可撤销、排队、记录日志
   - 备忘录模式：保存对象状态，后期可以恢复状态
   - 状态模式：对象状态改变时改变自身行为
   - 访问者模式：在不修改元素类前提下，新增对元素的操作
   - 中介者模式：用中介对象封装一组对象交互，降低耦合（迪米特）
   - 解释器模式：定义语言文法解释器，做语法解析（极少用）
